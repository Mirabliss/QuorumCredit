# Cost Allocation by Tenant/Feature (Issue #1227)

Operating costs for QuorumCredit weren't previously allocated by feature, which made it hard to answer "where should we invest to reduce cost" or "which feature is getting expensive to run." `server/src/costs/costAllocator.ts` addresses this with an activity-based allocation model.

## Cost inputs tracked

| Input | Source | Env var |
|---|---|---|
| Contract fees | Flat per-transaction estimate (Soroban resource fees vary by usage; the indexer doesn't decode actual fee-charged amounts today) | `CONTRACT_FEE_STROOPS_PER_TX` (default `100000` = 0.01 XLM) |
| API server hosting | Operator-supplied monthly hosting bill | `API_SERVER_MONTHLY_COST_CENTS` (default `0`) |
| Data storage | Operator-supplied monthly storage bill (indexer DB + backups) | `STORAGE_MONTHLY_COST_CENTS` (default `0`) |
| Stroops→USD conversion | Optional; without it, contract fees are reported natively in stroops and excluded from the blended `totalCostCents` rather than fabricating an exchange rate | `STROOPS_TO_CENTS_RATE` (unset by default) |

## Feature allocation

Every indexed on-chain event is mapped to a feature by its category (`tools/indexer/src/indexer.rs::decode_event`):

- `loan` events → **lending**
- `vouch` events → **vouching**
- `admin` events (pause/config/admin-set changes) → **governance**
- Everything else (`contract` lifecycle events, undecoded categories) → **other**

The API-server and storage cost inputs (which aren't tied to any single feature at the source) are allocated across features **in proportion to each feature's share of on-chain transaction volume** for the period. This is a simple, defensible activity-based costing approach — this service has no per-request cost tracing, so a transaction-volume proxy is used instead of pretending to have finer-grained attribution.

Cost per transaction by feature = that feature's total allocated cost ÷ its transaction count.

## Endpoints

- `GET /costs/report` — cumulative (all-time) report allocated using the currently configured monthly cost inputs. Add `?month=YYYY-MM` to scope to a single billing month's counts instead.
- `GET /costs/report/monthly` — one report per month that has recorded activity (the "generate monthly cost reports" deliverable).

Example response shape:

```json
{
  "generatedAt": 1769000000000,
  "period": "2026-07",
  "totalTransactionCount": 1204,
  "totalCostCents": 48000,
  "contractFeesIncludedInTotal": false,
  "features": [
    {
      "feature": "lending",
      "transactionCount": 820,
      "transactionShare": 0.681,
      "contractFeeStroops": 82000000,
      "apiServerCostCents": 27240,
      "storageCostCents": 6810,
      "totalCostCents": 34050,
      "costPerTransactionCents": 41.5
    }
  ],
  "optimizationHints": [
    "governance: allocated $12.00 of infra cost with zero recorded transactions this period — check for stranded capacity."
  ]
}
```

## Cost optimization opportunities

Each report includes `optimizationHints`, generated by comparing each feature's cost-per-transaction against the cross-feature average and flagging:

- A feature receiving infra cost allocation with zero transaction volume (stranded capacity).
- A feature whose cost per transaction is more than 2x the average across active features.

These are starting points for investigation, not conclusions — a feature can legitimately be more resource-intensive per transaction (e.g. governance actions touching more storage than a single loan request).

## Known limitation: leader-only accrual

Like `MetricsAggregator`, `CostAllocator` is fed from `Bridge`'s leader-only event tail loop (see `server/src/bridge/bridge.ts`). In a multi-replica deployment, only the instance currently holding the bridge leader lock has accurate cumulative counts. Query `/costs/report` against the leader, or expect per-instance drift after a leader handover — there's no shared store backing this today.

## Generating a monthly report file

`GET /costs/report/monthly` returns the full history in one call; to persist it as a file (e.g. for archival alongside the backup snapshots in `backups/`), pipe it through `jq`:

```bash
curl -s http://localhost:4000/costs/report/monthly | jq . > docs/cost-reports/$(date -u +%Y-%m).json
```
